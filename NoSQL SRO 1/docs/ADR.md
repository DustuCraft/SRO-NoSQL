# ADR-001: MongoDB для каталога электроники

**Статус:** принято  **Дата:** 2026-10-19

## Контекст
Каталог содержит товары разных категорий. У смартфона есть `battery_mah`, у ноутбука — `cpu`, у телевизора — `panel`.
Основные операции — чтение и фильтрация карточек по цене, категории и характеристикам, плюс аналитические агрегации.

## Рассмотренные варианты
| Критерий | MongoDB | PostgreSQL (JSONB) | Redis | Cassandra |
|----------|---------|--------------------|-------|-----------|
| Разнородные характеристики | Нативно (вложенный документ) | JSONB, менее удобные индексы | Нет | Плохо |
| Фильтр по диапазонам и нескольким полям | Составные индексы | Да | Нет | Только по ключу партиции |
| Агрегации | Aggregation pipeline | SQL | Нет | Ограничены |
| Полнотекстовый поиск | Text index | tsvector | Нет | Нет |
| Простота запуска | Высокая | Высокая | Высокая | Средняя |

## Решение
MongoDB. Карточка товара — самостоятельный документ, читается целиком одним запросом. Характеристики хранятся
**вложенным документом `specs`** (embedding), категория связана по `slug` (referencing: справочник маленький, меняется редко).

## Последствия
- (+) Нет миграций при добавлении характеристик, одна выборка на карточку, мощные агрегации.
- (−) Нет строгой схемы: нужна валидация на уровне приложения (при желании — `$jsonSchema`).
- (−) Индексы по `specs.*` нужно создавать под реальные запросы; полнотекстовый поиск проще, чем в Elasticsearch.
- Redis-кэш не вводится: нагрузка читающая, но индексы уже дают нужное время ответа (см. benchmark).
